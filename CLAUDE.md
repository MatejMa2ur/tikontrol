# tikontrol: notes for agents

- **Never publish real values from the user's setup.** This repo is public. Nothing real from their network goes into
  code, docs, tests, screenshots, commits or PRs: no names, hostnames, SSIDs, IP or MAC addresses, public IP, DDNS name,
  ports, traffic, signal, uptime, timestamps, versions, service state or free-capacity numbers. Use made-up values or
  `src/scripts/anonymize.py` output, and check the result first. `snapshot.json` stays local and is never committed.
- **docs/FEATURES.md is the progress tracker.** Whenever a feature or page changes state, update its Status cell
  (⬜ todo · 🎨 mockup · 🟨 in progress · ✅ done · ➖ won't do), then run `src/scripts/progress.py`.
  ✅ means real router data + tested, not just UI.
- Plan and rules live in docs/PLAN.md (simplicity rules §0.6, Safe apply §3). Research is in docs/RESEARCH.md.
- The router is the user's live home router. **Read-only unless the user
  approves a change.** Always pass explicit proplists/fields: `/ip/cloud/get` without a field leaks the BTH private key.
- UI mockup: `src/ui/` (Svelte 5 + Vite). Real data snapshot: `src/scripts/snapshot.py > src/ui/src/lib/snapshot.json` (gitignored);
  `src/ui/src/lib/sample.json` is the committed, fictional fallback, generated by `src/scripts/anonymize.py`. `?device=be3` simulates a hAP be³ Media.
- Hardware is detected, never configured: `src/ui/src/lib/hardware.ts`. Test it with `node --test tests/hardware.test.ts`.
