# tikontrol: notes for agents

- **Never publish real values from the user's setup.** This repo is public. Nothing real from their network goes into
  code, docs, tests, screenshots, commits or PRs: no names, hostnames, SSIDs, IP or MAC addresses, public IP, DDNS name,
  ports, traffic, signal, uptime, timestamps, versions, service state or free-capacity numbers. Use made-up values or
  `src/scripts/anonymize.py` output, and check the result first. `snapshot.json` stays local and is never committed.
- **docs/FEATURES.md is the progress tracker.** Whenever a feature or page changes state, update its Status cell
  (⬜ todo · 🎨 mockup · 🟨 in progress · ✅ done · ➖ won't do), then run `src/scripts/progress.py`.
  ✅ means real router data + tested, not just UI.
- Plan and rules live in docs/PLAN.md (simplicity rules §0.6, Safe apply §3). Research is in docs/RESEARCH.md.
- The router is the user's live home router. **Read-only unless the user
  approves a change.** Always pass explicit proplists/fields: `/ip/cloud/get` without a field leaks the BTH private key.
- UI mockup: `src/ui/` (Svelte 5 + Vite). Real data snapshot: `src/scripts/snapshot.py > src/ui/src/lib/snapshot.json` (gitignored);
  `src/ui/src/lib/sample.json` is the committed, fictional fallback, generated by `src/scripts/anonymize.py`. `?device=be3` simulates a hAP be³ Media.
- Hardware is detected, never configured: `src/ui/src/lib/hardware.ts`. Test it with `node --test tests/hardware.test.ts`.

## Security rules (mandatory)

tikontrol holds credentials that can change a whole router. A write credential equals admin. Treat every change as security work.

- **Least privilege.** Separate reader and writer RouterOS users in custom groups. Never use the built-in `read` group: it includes `sensitive` and `reboot`.
- **Secrets.** Encrypt router credentials at rest. Never put secrets in code, logs, error messages, API responses, MCP output, URLs or the browser.
- **Transport.** Use the binary API over TLS (8729) and verify the certificate. Never use plain 8728, telnet, FTP or HTTP.
- **Access.** Every backend and MCP endpoint needs authentication and authorisation, denied by default, with CSRF protection and rate limiting on login. Nothing is exposed to the internet by default.
- **Untrusted data.** Hostnames, SSIDs, DHCP fields, logs and comments come from other devices. Escape them in the UI, never build RouterOS commands by joining strings, and treat them as prompt injection risks in MCP.
- **Input.** Validate all input on the server, at the trust boundary, even when the UI already checks it.
- **Writes.** Read-only by default. Every write goes through Safe apply, must be confirmed from the user's browser and must have a tested rollback. High-risk changes (VLAN filtering, input firewall, `/ip/service`, management addresses) need explicit warnings.
- **Containers.** Run as non-root, never privileged, with `memory-max` set and our own pinned image.
- **Dependencies.** Keep lockfiles committed, add as few as possible, and check `npm audit` (and `cargo audit` once Rust exists) before each release.
- **Privacy.** No telemetry or outbound calls by default. Anything sent to a third party, including an AI provider, must be opt-in and clearly labelled.
- Review security-sensitive changes with `/security-review` before merging. Report weaknesses honestly, never hide them.

## Standards (mandatory)

- **Security:** OWASP ASVS and OWASP Top 10 for the web app, OWASP API Security Top 10 for the backend.
- **Accessibility:** WCAG 2.2 AA: keyboard use, visible focus, labels, and contrast in both themes.
- **Code:** TypeScript strict, `npm run check` clean, no ignored errors. Follow the patterns already in the repo.
- **Tests:** logic that parses router data, builds commands or touches security needs a test. Run `node --test tests/hardware.test.ts` and the build before committing, and never claim something works without running it.
- **APIs:** document the backend API with OpenAPI, version it, and follow the MCP specification for MCP.
- **RouterOS:** feature-detect instead of assuming a version, and support a stated minimum version (7.18 for the API, 7.25 for REST).
- **Releases:** Semantic Versioning and a changelog. Commit messages follow the existing `type(scope): subject` style.
- **Legal:** original icons, colours and layout. No Ubiquiti or MikroTik logos, code or product images, and keep the non-affiliation notice.
